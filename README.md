# Стартовый код — кейс «Граф денег»

Чтобы вы не тратили час из пяти на загрузку parquet и сборку графа.

## Запуск

```bash
pip install -r requirements.txt
python starter.py
```

На выходе рядом со скриптом — `out/nodes_roles.csv`, `out/clusters.csv`, `out/top_nodes.csv` в схеме из ТЗ. По умолчанию входные parquet-файлы читаются из `parquet/`; папка вывода создаётся автоматически. Пути можно переопределить через `--data` и `--out`.

## Что уже посчитано

| Колонка | Смысл |
|---|---|
| `in_deg` / `out_deg` | от скольких разных клиентов получил / скольким разным отправил |
| `in_kzt` / `out_kzt` | сколько получил / отправил в тенге **внутри графа** |
| `in_tx` / `out_tx` | количество переводов |
| `pagerank` | взвешенный по сумме PageRank |
| `pass_through` | `out_kzt / in_kzt` — доля полученного, ушедшая дальше |
| `truncated_by_depth` | узел на 4-м колене без исходящих |
| `depth`, `is_seed` | из `nodes.parquet` |

## Четыре ловушки, на которых ломаются наивные решения

**1. `out_deg == 0` не значит «деньги осели».**
444 узла лежат на 4-м колене — обход просто закончился на них. Настоящий ли это конечный получатель или у него есть переводы дальше, которых нет в выгрузке, — по этим данным напрямую не видно. Придумайте, как их различить, и объясните логику.

**2. У seed-клиентов `in_kzt` занижен.**
Граф собран **от** seed по исходящим. Деньги, которые seed получил извне выборки, в данных отсутствуют. Поэтому `pass_through` у них бывает 20 и больше — это не аномалия, это устройство выгрузки. Не стройте роль на «сколько получил» для seed вслепую.

**3. Суммы и количество переводов — разные сигналы.**
Один перевод на 4 млн и сорок переводов по 100 тыс. дают одинаковый `in_kzt`, но означают разное поведение. Смотрите обе величины.

**4. Граф направленный и взвешенный.**
`nx.degree_centrality` на неориентированной проекции сотрёт всю суть кейса — направление движения денег. Если используете ненаправленные методы (например, кластеризацию), оговорите это явно.

## Требования к выгрузкам

Схема зафиксирована в ТЗ, жюри проверяет её механически:

- `nodes_roles.csv` — ровно **2 248 строк**, все колонки заполнены, `evidence` содержит числа, а не «высокий скор»;
- `clusters.csv` — строка на кластер, включая гипотезу о его назначении;
- `top_nodes.csv` — **не менее 20** строк, отсортированных по приоритету.

Лишние колонки добавлять можно, обязательные удалять — нет.

## Интерпретация кластеров и рейтинга

Кластеры строятся алгоритмом Louvain на **неориентированной проекции** графа: веса направленных рёбер между парой клиентов складываются, поэтому направление потока при назначении сообществ теряется. Внутренний оборот `sum_kzt_internal` при этом считается по исходным направленным рёбрам, а изолированные клиенты включаются в граф как отдельные одноузловые кластеры. `top_gids` содержит до пяти участников с наибольшим суммарным внутренним инцидентным оборотом.

Гипотезы в `clusters.csv` описывают только наблюдаемые размеры, связи, обороты и признаки транзита/множественных контрагентов. Они являются осторожными описаниями возможной функции группы, а не утверждениями о нарушениях.

`top_nodes.csv` ранжирует клиентов по детерминированной смеси уже рассчитываемых сигналов: `role_score` (50%), нормированный `log1p(in_kzt + out_kzt)` (30%) и нормированный взвешенный PageRank (20%). В `why` приведены индивидуальные входящие и исходящие контрагенты, суммы, pass-through, PageRank и кластер. У seed-клиентов входящие потоки могут быть неполными, поэтому их pass-through не трактуется как самостоятельное подозрение. Узлы на глубине 4 без исходящих рёбер могут быть обрезаны сбором; это не доказывает, что они являются конечными получателями или ведут себя подозрительно.

В `nodes_roles.csv` неопределённый `pass_through` (нет наблюдаемого входящего оборота) записывается как `0` для заполненного числового экспорта; `in_deg` и `in_kzt` позволяют отличить такой случай от рассчитанного нулевого отношения.

## Подсказки по инструментам

```python
import networkx as nx

nx.pagerank(G, weight="sum_kzt")            # влияние узла
nx.hits(G)                                   # хабы и авторитеты — разделяет источники и сборщиков
nx.betweenness_centrality(G, weight=...)     # посредничество: кто «между»
nx.community.louvain_communities(UG)         # кластеры (на неориентированной проекции)
nx.simple_cycles(G, length_bound=6)          # возвратные потоки
nx.weakly_connected_components(G)            # изолированные фрагменты сети
```

`transactions.parquet` не использован в стартовом коде намеренно — там лежат даты, а временны́е паттерны дают дополнительные баллы.

## Что оценивается выше всего

Не количество метрик, а то, **сможете ли вы за минуту объяснить жюри, почему конкретный `gid` получил свою роль.** Считайте столько, сколько сможете защитить.
